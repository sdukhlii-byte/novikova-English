# Бот-квиз для сбора заявок: преподаватель английского для детей

Telegram-бот для привлечения клиентов (родителей) через рекламу. Родитель за минуту проходит квиз из 6 вопросов,
получает персональную рекомендацию и оставляет заявку на бесплатный пробный урок. Преподаватель получает готовую
карточку лида с ответами и кнопками статусов, а владелец рекламы видит воронку и цену заявки.

## Как это работает

```
Реклама (Telegram Ads) → /start <метка> → квиз (6 шагов) → рекомендация → заявка → карточка преподавателю
                                                                 ↓                     ↓
                                                        автодогрев (1ч/24ч/72ч)   Google Sheets + статусы
```

- **Квиз:** возраст, цель, уровень «по ощущению родителя», главная сложность, формат, удобное время. Экран обновляется на месте, есть прогресс и кнопка «Назад». Тестов на знание английского нет.
- **Рекомендация:** собирается из ответов (с чего начать, на чём сделать упор, какой формат). Для группового формата подставляется группа по возрасту («Учимся читать» 1–2 класс, «Учимся легко» 3–4 класс, «Разговорный клуб» 5–7 класс, словарь `GROUPS`). Всё редактируется в `bot/content.py`.
- **Заявка:** имя, страна, телефон (необязателен, если есть @username), явное согласие на обработку данных.
- **Карточка преподавателю:** ответы квиза, контакт, источник, кнопки `Связались / Назначить пробный / Оплатил / Не подошло`.
- **Пробный урок:** преподаватель отправляет `25.10 18:00 ссылка`, клиент получает подтверждение, затем напоминания за сутки и за час.
- **Переписка через бота:** сообщения клиента приходят преподавателю, ответом (reply) на сообщение или карточку она пишет клиенту.
- **Автодогрев:** цепочка из 5 касаний за 7 дней тем, кто прошёл квиз, но не записался; бросившим квиз на середине 2 напоминания (подробности в разделе «Догрев» ниже). Только 09:00–21:00, в каждом сообщении есть «Не напоминать».
- **Мини-проверка «Найди ошибку»:** бонус после результата квиза в фирменном формате преподавателя: 4 предложения с ошибкой, родитель показывает ребёнку и смотрит ответ с пояснением. Тексты в `MINI_CHECK` файла `bot/content.py`; пустой список убирает кнопку.
- **Возражения:** кнопки с ответами «Как проходит пробный?», «А если ребёнок стесняется?», «Неудобное время», «Сколько стоят занятия?» в напоминаниях, в меню и в `/faq`.
- **Google Sheets:** каждая заявка и смена статуса дублируются в таблицу (необязательно).

## Догрев: углы влияния и A/B

Цель: довести родителя до **записи на пробный урок**. Каждое касание бьёт в свою причину, по которой люди не записываются, а тексты подстраиваются под ответы квиза (главную сложность и цель ребёнка).

| Когда | Угол | Что делает |
|---|---|---|
| +1 ч | Продолжение | возвращает к уже собранному плану, подсказка по сложности ребёнка (`{pain_hook}`) |
| +24 ч | Снятие неопределённости | «как проходит пробный», «а вдруг не понравится», кнопки возражений |
| +48 ч | Социальное доказательство | реальный отзыв родителя (из `TEACHER["reviews"]`); пока отзывов нет, показывается «чего ждать от первых недель» |
| +4 дня | Польза | мини-совет родителям под сложность ребёнка (`PAIN_TIP`), дающий ценность без просьбы записаться |
| +7 дней | Мягкое закрытие | либо честное «последнее напоминание», либо опрос «что остановило?» (его ответы копятся в статистике) |
| +2 ч / +26 ч | Недоделанный квиз | «осталось N вопросов», ответы сохранены |
| +1 ч / +24 ч после мини-проверки | Игра → квиз → пробный | тем, кто сыграл в «найди ошибку» и не начал квиз: подобрать программу, затем как проходит пробный |
| +3 ч / +30 ч после первого /start | Открыл и ушёл | тем, кто ничего не нажал: 6 вопросов за минуту, затем запись без квиза |

Тот, кто пришёл с метки `game`, считается отдельной ступенью воронки: `/stats` показывает, сколько человек начали и прошли мини-проверку и сколько продолжили в квиз.

**A/B-треки.** Каждый клиент закреплён за треком (`a` или `b` по чётности id): `a` информационный, `b` вовлекающий (вопрос, лёгкий следующий шаг). `/stats` показывает, сколько заявок принесло каждое сообщение и каждый трек. Заявка засчитывается последнему напоминанию, полученному за 36 часов до неё. Решения принимайте от ~30 получателей на трек, раньше это шум.

**Защита от спама.** Только 09:00–21:00 по `FOLLOWUP_TZ`; если бот лежал, отправляется только самое свежее наступившее сообщение, не вся цепочка; клиент, написавший преподавателю, ставится на паузу на 3 дня; «Не напоминать» и ответ «пока не актуально» отключают догрев навсегда.

**Принципы.** Никакого выдуманного дефицита («осталось 2 места», «акция до вечера») и ложных дедлайнов: они ломают доверие родителей и могут нарушать правила рекламы. Дефицит допустим только настоящий (например, «на этой неделе остались 2 слота»), тогда впишите его в текст самостоятельно.

**Что вписать, чтобы догрев заработал в полную силу:** отзывы (`TEACHER["reviews"]`), ответ про цену (`OBJECTIONS`, id `price`), а также проверить дефолтные тексты возражений, что они правда про вас. Все тексты касаний лежат в `FOLLOWUPS` и `UNFINISHED` файла `bot/content.py`.

## Быстрый старт (локально)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # заполните BOT_TOKEN и TEACHER_CHAT_ID
python -m bot.main
```

1. Создайте бота у [@BotFather](https://t.me/BotFather), токен в `BOT_TOKEN`.
2. Запустите бота и отправьте ему `/id`. Это ваш user id и id чата. Преподаватель делает то же самое.
3. `TEACHER_CHAT_ID` — id личного чата преподавателя (она должна один раз нажать /start у бота) **или** id группы.
4. `ADMIN_IDS` — id людей, которые могут нажимать кнопки статусов и видеть статистику (вы и преподаватель). Если заявки идут в **группу**, впишите сюда оба id.

## Заявки в общую группу (рекомендуется)

1. Создайте группу в Telegram (например, «Заявки · English»), добавьте в неё преподавателя, себя и бота.
2. Отправьте в группе `/id` (если в группе несколько ботов, `/id@имя_бота`). Бот ответит «Id этого чата: -100…».
3. В переменных: `TEACHER_CHAT_ID=-100…` (число с минусом целиком) и `ADMIN_IDS=<id преподавателя>,<ваш id>`. Свои user id каждый узнаёт командой `/id` в личке бота. **ADMIN_IDS в группе обязателен**: только эти люди могут нажимать кнопки статусов и писать клиентам через бота. Остальные участники группы видят карточки, но управлять ими не могут.
4. Настройки приватности бота (privacy mode) менять не нужно: ответы на сообщения бота он получает и так.

Что работает в группе: карточки заявок, кнопки статусов, назначение пробного (дату нужно отправить **ответом** на сообщение бота «Отправьте дату…»), переписка с клиентом (ответ reply на сообщение или карточку), `/stats`, `/leads`, `/export`. Участники группы не попадают в статистику воронки как клиенты.

Если Telegram превратит группу в супергруппу (например, при включении тем или истории чата), её id изменится: узнайте новый через `/id` и обновите `TEACHER_CHAT_ID`.

## Что отредактировать до запуска рекламы

Всё в одном файле: **`bot/content.py`**. Пустые поля просто не показываются, поэтому бота можно запускать сразу.

| Блок | Что вписать |
|---|---|
| `TEACHER` | имя, опыт, о себе, дипломы/сертификаты, подход, результаты, отзывы |
| `TEACHER["photo"]` | положите фото в `assets/teacher.jpg` |
| `TEACHER["response_time"]` | как быстро она отвечает: «в течение 2 часов с 9:00 до 20:00» |
| `TRIAL` | длительность и состав пробного урока |
| `CHOICE`, `*_PLAN` | вопросы квиза и тексты рекомендации |
| `FOLLOWUPS` | тексты догрева |

Переменные окружения: `PRIVACY_URL` (ссылка на политику конфиденциальности, для рекламы в ЕС желательно иметь), `TEACHER_TZ` (часовой пояс преподавателя, по умолчанию Москва: по нему она назначает время пробного; клиенту из Европы бот показывает время ещё и по его часам, страну он указывает в заявке).

## Деплой на Railway

Бот работает на long polling: порт и вебхук не нужны.

1. Загрузите репозиторий на GitHub (файл `.env` не загружайте, он в `.gitignore`).
2. Railway → **New Project → Deploy from GitHub repo**. Используется `Dockerfile`, команда запуска `python -m bot.main`.
3. Вкладка **Variables → Raw Editor**: вставьте переменные из `.env.example` (`BOT_TOKEN`, `TEACHER_CHAT_ID`, `ADMIN_IDS`, `DB_PATH=/data/bot.db`, `GOOGLE_SHEET_ID`, `GOOGLE_CREDS_B64`, `PRIVACY_URL`, `TEACHER_TZ`, `FOLLOWUP_TZ`, `FOLLOWUPS_ENABLED`, `CONTACT_USERNAME`).
4. **Важно:** сервис → **Settings → Volumes → Add Volume**, Mount Path `/data`. Без тома база заявок стирается при каждом деплое.
5. В **Settings → Networking** публичный домен создавать не нужно. Запускайте ровно **один** экземпляр (Replicas = 1): два бота с одним токеном дают ошибку Telegram `Conflict`, не запускайте тот же токен локально.
6. После деплоя напишите боту `/id` (и в группе заявок тоже), впишите полученные id в `TEACHER_CHAT_ID` и `ADMIN_IDS`; Railway перезапустит сервис сам.

`GOOGLE_CREDS_B64`: `base64 -w0 key.json` (macOS: `base64 -i key.json`). Логи: вкладка **Deployments → View logs**, строка `Автодогрев запущен` означает, что всё поднялось.

## Google Sheets (по желанию)

1. В Google Cloud создайте сервис-аккаунт, включите Google Sheets API и скачайте JSON-ключ.
2. Создайте таблицу, дайте доступ редактора на e-mail сервис-аккаунта (`...iam.gserviceaccount.com`).
3. `GOOGLE_SHEET_ID` — часть URL таблицы между `/d/` и `/edit`. `GOOGLE_CREDS_JSON` — содержимое JSON-ключа одной строкой (или `GOOGLE_CREDS_B64`, если панель хостинга ломает кавычки).

Лист `Leads` и заголовки бот создаст сам.

## Реклама и метки источников

Ссылка на бота с меткой: `https://t.me/<имя_бота>?start=tgads_cr1`. Метка (латиница, цифры, `_`, `-`, до 64 символов) сохраняется как источник лида. Для каждого креатива или канала используйте свою, например `tgads_cr1`, `tgads_cr2`, `chan_mamy_riga`.

**Метки с `game`** (например `tgads_game1`) открывают сразу мини-проверку «Найди ошибку» вместо общего приветствия: так человек из рекламы «найдите ошибку» попадает ровно в то, что обещало объявление. После последнего предложения бот предлагает подобрать программу (квиз) или записаться.

**Команды для админа:**

| Команда | Что делает |
|---|---|
| `/stats` или `/stats 14` | воронка по источникам за N дней (по умолчанию 7) |
| `/stats 7 150` | то же и расчёт цены: CPL, цена завершённого квиза, пробного и оплаты при расходе €150; внизу блок «Догрев»: какое сообщение и какой трек приводят заявки, причины отказа из опроса |
| `/leads` | последние 10 заявок |
| `/export` | все заявки файлом CSV (открывается в Excel) |
| `/id` | показать свой user id и id чата |

Сам преподаватель и админы в статистику воронки не попадают, поэтому тестировать бота можно спокойно.

## Клиентские команды

`/start`, `/about`, `/faq`, `/contact`, `/privacy`, `/delete` (удаляет все данные клиента, включая строку в Sheets).

## Проверка

```bash
python -m tests.smoke_flow
```

Прогоняет весь сценарий на подменённом Telegram API (квиз, заявка, карточка, пробный, переписка, статистика, догрев, удаление данных) и печатает переписку.

## Структура

```
bot/
  content.py      ← ВСЕ тексты и данные преподавателя
  texts.py        сборка экранов и карточки
  keyboards.py    клавиатуры
  db.py           SQLite (состояние диалога хранится в базе и переживает рестарт)
  sheets.py       Google Sheets
  followups.py    автодогрев и напоминания о пробном
  cards.py        карточка заявки
  handlers/       common · quiz · mini · lead · staff
tests/smoke_flow.py
```

## Заметки

- Для рекламы в Telegram Ads текст объявления не должен обещать гарантированный результат («выучит за месяц»).
- Бот собирает персональные данные родителей в ЕС. Держите на сайте или в Telegraph страницу с политикой конфиденциальности и укажите её в `PRIVACY_URL`.
- Если нужна мини-апка с лендингом (для A/B-сравнения), квиз и заявки можно переиспользовать: логика лежит в `handlers/` и `db.py`.
